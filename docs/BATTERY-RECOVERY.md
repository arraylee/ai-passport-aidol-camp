# v0.7.4 电量自动恢复

## 原因与处理
翻页器窗口的RAM只读诊断曾在尾号32ED54测到VERSION=0x0f，电压约4.12V，但SOC=254+232/256（无效），80字节电芯参数全0、UPDATE_FLAG未设。ESP32重启不会补齐外部CW2017的参数；这不是好友/成绩脏数据，电压也不能直接当成百分比。

固件使用当前BSP既有80字节表，与本地Aidol固件board_config.h选择的CW2017_PROFILE_SEL=1（4.2v_520mah）逐字节一致。只对全0、全FF、或已识别为本程序顺序写入中断的参数自动完成初始化；已提交的正常非空参数保留，即使与内置表不同。未提交且不认识的非空参数保留并记录错误，不盲目覆盖。

按CONFIG 0x30→等待20ms→0xf0→等待10ms进入休眠，逐字节写80字节并读回校验，再提交/回读UPDATE_FLAG，最后0x30→20ms→0x00→10ms唤醒。若空表残留提交标记，先清除并确认；写入或校验失败不当作有效。重试退避1/2/4/8/30秒，最长30秒。写入中断后下次继续；不在每次采样/重启时重刷正常表。

前台每次服务最多一个5ms I2C事务，不新增任务，不调用等待延时。正常5秒采样；未知/失败1秒采样；3次坏SOC请求重新检查和重启计算，恢复间隔至少30秒。短暂失败保留缓存，最后有效样本超过30秒则显示未知。业务忙碌也能推进恢复，但不会把电量读取算成用户操作，不改变20分钟休眠。

## 界面与数据
灰色电池内横线表示未知/恢复中；有效0%为红色空框；正常值显示填充量，不显示数字。恢复电量的运行时代码只写CW2017寄存器，不写Flash、原SN、NVS、头像、好友、成绩或激活状态；网页整包升级覆盖原普通NVS的行为沿用既有打包方式，分段升级保留。

## 实机验收
1. 多台统一升级后开机停首页，等待几秒观察电池恢复；日志应出现repair、prepared=1和0..100 SOC。不存在电量计/电芯真实故障时仍可能保持未知，不伪造百分比。
2. 重启和休眠唤醒后图标应恢复；已完成表不应再次逐字节写入。
3. 拔掉USB使用、充电后对照图标变化，确认SOC变化合理。约4.12V不能证明已满电，六小时续航仍需实测。
4. 同时两台交换名片，测试首次、重复交换、长下取消再交换、某台短时离线/重连；每台应看到对方资料。失败可短下重试，长下始终回首页。

## 本轮证据边界
实际BSP寄存器模拟器覆盖80字节写/回读、空/FF表、正常不同校准保留、若干位置断电恢复、丢提交/校验失败、缺失芯片重连、睡眠/唤醒、时钟回绕、单步事务上限。电源缓存/失效/业务繁忙/休眠和原LVGL渲染另测。

用户复现未连USB一台100%、连USB一台0%。原v0.7.3只读串口180秒持续有心跳和健康日志，无捕获到CPU panic；串口打开触发USB重启一次。主机模拟确认旧代码在单边保存后丢失传输状态时不能再补发；v0.7.4支持已验证快照恢复，旧快照不自动改成未请求的新资料。实机卡顿的完整触发链尚未证实，新版修复和电量自动补齐均未刷机验收。
