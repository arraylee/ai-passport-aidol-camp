# Bluetooth management v1

Helper v0.3.0 requires firmware v0.7.0, v0.7.1, v0.7.2 or v0.7.3. Existing profile GATT service and miniapp remain compatible. One BLE central per badge, desktop manages two badges concurrently and queues up to six.

Service: 54524145-4341-5244-0000-000000000000. Existing command/notification/identity characteristics end in0010/0011/0012. Added read-only management status ends in0020. Original72-byte identity remains unchanged and contains no secret.

Management command uses existing frame `[1,type,u16le length,payload]`, type0x30. Payload18 bytes: protocol1, action(1=restore,2=clear), role1..6, reserved0, connection nonce u32le, nonzero transaction u32le, expected Wi-Fi MAC6. A clear request must keep current role. Matching duplicate transactions do not erase again; conflicting or malformed commands fail before writes. Response notification `[0x30,0]` means accepted, never completed. Poll status until matching transaction/state3, then transfer text/avatar through existing commands and verify actual committed pixelCRC.

Status228 bytes: magicHBC1[0:4], protocol[4], role[5], volume[6], activated[7], MAC[8:14], SN null-terminated25[14:39], firmware16[39:55], name49[55:104], signature85[104:189], uptime_u32[189], physical boot token_u32[193], runtime reset counter_u32[197], profile revision_u32[201], committed imageCRC_u32[205], transaction_u32[209], state[213], progress[214], error[215], connection nonce_u32[216], friendsmask[220], best_valid[221], best_u32[222], custom_gallery[226], welcome_seen[227]. States0=idle,1=erasing,2=applying,3=done,4=error. Scalars little-endian. Physical boot token is generated once per BLE initialization, never changed by management reset.

A separate `demo_cfg/ble_config/pending` record is committed before destructive reset. Main task erases one4KiB sector per iteration in exact named profile(0x380000+0x30000), friend(0x3b0000+0x30000), gallery(0x400000+0xc0000) partitions. Clear skips profile. Then only the hideseek namespace in demo_cfg is reset. Original NVS/cardid/code/partition table are excluded. Durable marker is removed only after settings and in-memory stores reload successfully; interrupted cleanup resumes after next startup. Failed cleanup remains unavailable for gameplay until retry/recovery.

Runtime core, persona, friend/gallery references and pending input/save/intro states are refreshed while keeping the same BLE connection. No esp_restart or BLE stack restart. New profile PNG uses the existing dual-bank validated decoder. Host verifies MAC/SN/boot token, incremented reset counter, role/name/signature/pixelCRC, no friends/best/custom album/activation/welcome, volume90. Success requires device status readback, not only host write completion.

Validation: tests/test_configure.c exercises request guards/idempotence/recovery; tests/test_config_storage.py runs real erase adapter over an8MB array; desktop protocol/link tests use real framing and device-state fakes; existing host and tool suites plus IDF5.5.3 build/size. Real old-firmware discovery/identity succeeds on this Mac. Actual new-firmware state/reset/avatars/audio recovery and6-device concurrency are pending physical acceptance.
